## Требования

Разработка рассчитана на Windows, Linux и macOS. Для команд терминала нужен
[uv](https://docs.astral.sh/uv/getting-started/installation/) и интернет
при первой установке зависимостей. VS Code с PlatformIO IDE удобен для
работы с платой; Wokwi Simulator нужен для симуляции.

Из корня проекта:

```text
uv sync --locked
uv run python -m tools.check
```

uv подготовит Python 3.13 и зависимости из [uv.lock](../uv.lock).
Активировать виртуальное окружение вручную не требуется. PlatformIO
загружает инструменты AVR и Arduino framework. Для нативных тестов используется
Zig из Python-пакета на Windows и Linux. На macOS используется Apple Clang из
Xcode Command Line Tools (`xcode-select --install`), чтобы компилятор работал
с установленным SDK. Отдельно устанавливать Visual Studio, MinGW, CMake
или Node.js не нужно. Версии и настройки инструментов — в
[pyproject.toml](../pyproject.toml) и [platformio.ini](../platformio.ini).

## Сборка прошивки

```text
uv run python -m platformio run
```

По умолчанию собирается `uno`: DS1307, русский интерфейс.
Другой профиль выбирается через `-e`:

| Профиль | Часы | Язык |
| --- | --- | --- |
| `uno` | DS1307 | Русский |
| `uno-ds3231` | DS3231 | Русский |
| `uno-en` | DS1307 | Английский |
| `uno-ds3231-en` | DS3231 | Английский |

Пример:

```text
uv run python -m platformio run -e uno-ds3231
```

Результаты лежат в `.pio/build/<профиль>/`. Комплектный `wokwi.toml` читает
только профиль `uno`: сборка другого профиля сама по себе не переключает
симуляцию. Для другого профиля измените пути к HEX и ELF в `wokwi.toml`.

Если PlatformIO уже установлен отдельно, доступна команда `pio run`.
Подключение, симуляция и загрузка по USB описаны в [getting-started.md](getting-started.md).

## Проверки

[tools/check.py](../tools/check.py) — общий запуск проверок для локальной
работы и CI: линтер, форматирование, типы, pytest, переводы, четыре сборки.
Он останавливается при первой ошибке. Отдельные команды и границы тестовых
стендов описаны в [testing.md](testing.md).

В VS Code доступны задачи из [.vscode/tasks.json](../.vscode/tasks.json):

| Задача | Назначение |
| --- | --- |
| **Build firmware** (`Ctrl+Shift+B`) | Сборка профиля по умолчанию через uv |
| **Run tests** | Запуск pytest |
| **Check project** | Полная проверка через `tools.check` |

GitHub Actions использует ту же полную проверку в трёх ОС.
Конфигурация CI не заменяет результатов конкретного запуска: последнее
локальное выполнение описано в [verification.md](verification.md).

## Где менять проект

- [config/settings.h](../config/settings.h) — пины, управляющий уровень, RTC,
  язык, подсветка и таймаут ручного режима.
- [config/channel_names.h](../config/channel_names.h) — собственные имена каналов.
- [config/locales/](../config/locales/) — редактируемые надписи; правила в [i18n.md](i18n.md).
- `src/core/` — состояния помп, расписание, хранение программы и цикл приложения.
- `src/platform/` — Arduino-реализация GPIO, времени, RTC и EEPROM.
- `src/ui/lcd/` — ввод, редакторы и отображение.
- `tests/` — Python-сценарии и C++ адаптеры настоящего кода прошивки.

Внутренние заголовки лежат рядом с реализацией. Новую логику размещайте
в core, аппаратные вызовы — в platform, взаимодействие с пользователем —
в соответствующем интерфейсе. Направление зависимостей и модель состояний
подробнее описаны в [architecture.md](architecture.md).

## Локальные файлы

`.pio/`, `.venv/`, кэши и `.omo/` не нужны в репозитории.
Постоянные утилиты пишем на Python в `tools/`, сценарии — в `tests/`,
инструкции и принятые решения — в `docs/`. Временные журналы и результаты
работы агентов остаются локальными.
