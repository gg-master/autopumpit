# Архитектура проекта

[Главная](../README.md) · [Все документы](README.md)

Пользователь редактирует config/settings.h, config/channel_names.h и каталоги
config/locales/. Внутренние заголовки лежат рядом с реализацией в src/.
Отдельного публичного C++ SDK у прошивки пока нет, поэтому общего include/ нет.

## Структура

```text
config/                 Пользовательские параметры, имена и переводы
src/core/               Состояния помп, расписание, EEPROM и цикл приложения
src/platform/           Адаптер Arduino: GPIO, время, RTC, EEPROM
src/ui/lcd/             Меню, редакторы, энкодер и вывод на LCD
src/main.cpp            setup/loop: подключение LCD-контроллера
lib/                    Исходные Arduino-библиотеки
tools/                  Python-утилиты
tests/                  Python-сценарии и C++ адаптеры
docs/                   Инструкции и устройство проекта
```

Сборка задаётся в [platformio.ini](../platformio.ini), инструменты разработки —
в [pyproject.toml](../pyproject.toml). Их установка описана в
[development.md](development.md).

## Ответственность модулей

Зависимости направлены от интерфейса к логике:

- src/core/pump_control — единственный владелец состояния помп, таймеров, очереди и GPIO.
- src/core/rtc_schedule — единственный владелец программ (пауза, работа, срок) и журнала EEPROM.
- src/core/program_settings — операции настройки/сброса и запуск программы; собственных копий настроек нет.
- src/core/concurrency_settings — общий лимит, EEPROM 632–647, две записи с CRC16.
- src/core/calendar — преобразование дат и ограничения полей без LCD/RTClib.
- src/platform/ports.h — небольшой контракт времени, выходов, часов и хранилища.
- src/platform/arduino.cpp — реализация этого контракта для Arduino и библиотек.
- src/core/application — общий цикл RTC → завершение доз → ввод → допуск новых запусков;
  состояния работы, обязательной/обычной настройки часов и ошибки.
- src/ui/lcd/application — обработка меню, редактор часов и обновление LCD.
- src/ui/lcd/controller — аппаратный адаптер энкодера, LCD и подсветки.
- src/ui/lcd/auto_editor — черновик и редактор автоматической программы.
- src/ui/lcd/manual_ui — переходы ручного меню; manual_view — его отображение.
- src/ui/lcd/i18n и calendar_ui — вывод строк и календарных полей на LCD.

Core не включает Arduino, LCD, энкодер или заголовки интерфейса. Его алгоритмы
вызывают только аппаратный контракт. Тесты подставляют свою реализацию портов.
При добавлении другого интерфейса можно использовать существующие API core
и заменить подключение LCD в main.cpp. LCD-состояние и черновики не входят в core.
Проверка RTC, запрет полива при настройке часов и переходы Save/Cancel/Fault
принадлежат core/application. LCD отвечает за ввод и отображение. Прошивка и
нативные стенды вызывают один цикл приложения; отдельной реализации цикла
в тестовых адаптерах нет.

Во время реальной работы подключается только Arduino-адаптер. Файлы tests/
не попадают в прошивку. Нативные тесты компилируют тот же C++, а не копию
алгоритма полива на Python. Узкие C++ адаптеры тестов передают команды и
состояние; сценарии и проверки результатов написаны на Python.

Допуск новых запусков принадлежит pump_control: общий лимит Auto/Manual,
ручная FIFO-очередь перед новыми Auto; Auto — по сроку и номеру помпы.
При снижении лимита начатые дозы завершаются. Время ручных запусков хранится
отдельно по каждому каналу; LCD не управляет выходами и EEPROM напрямую.

Утилиты в tools/ и интеграционные сценарии в tests/ пишем на Python.
C++ адаптеры в tests/ служат для запуска настоящего кода прошивки.
Эти правила и направление зависимостей — соглашения для разработки и ревью,
а не отдельные автоматические тесты структуры исходников.

## Состояния и переходы

Состояния помпы: AutoIdle, AutoRunning, ManualIdle, ManualQueued, ManualRunning.
Один таймер используется для текущей работы либо ожидания выхода из Manual.
Исходная длительность и предлагаемый остаток принадлежат той же записи помпы.
Ручной запуск только точечный: выбор Manual, затем Start выбранной помпы.
Единый переход завершения обслуживает Stop, истечение времени и общий останов.
Сброс выбранной программы напрямую отменяет её работу/очередь, затем записывает
нулевую программу; промежуточного переключения в Manual и записи паузы нет.

Поля Auto-редактора именованы; таблица определяет порядок навигации и
соответствие календарным и временным компонентам. Числовых диапазонов экранов нет.
