# Тестирование

[Главная](../README.md) · [Все документы](README.md)

Установка инструментов описана в [development.md](development.md).
Полная проверка проекта: `uv run python -m tools.check`. Эта команда
одинакова локально и в GitHub Actions. Python-зависимости разработки
не попадают в память Arduino.

## Отдельные проверки

~~~text
uv run python -m pytest
uv run python -m pytest tests/integration
uv run python -m pytest tests/ui
uv run python -m tools.check_translations
uv run ruff check tools tests
uv run ruff format --check tools tests
uv run basedpyright
uv run python -m platformio run -e uno -e uno-ds3231 -e uno-en -e uno-ds3231-en
~~~

Набор pytest автоматически компилирует настоящие исходники C++ во временный
каталог. Каждый сценарий запускает изолированный процесс с управляемыми
временем, GPIO, RTC и EEPROM. Очередь и CRC не переписаны на Python.
Файлы .pio/, .venv/ и локальные журналы не нужны для запуска тестов.

Покрываются:

- Очередь всех 14 помп, ранние сроки и равенство сроков, обе полярности реле.
- Ручные времена каждой помпы, валидация, Stop, ожидание Auto и его прерывание.
- Сохранение настроек, перезапуск до/после срока, незавершённая доза, RTC-ошибки.
- Обрыв записи EEPROM на каждом шаге и повреждение каждого байта записи.
- Переполнение millis, календарные границы и преобразование 1200 дат.
- Инициализация GPIO без активного импульса при обеих полярностях реле.
- Настоящее LCD-меню на обоих языках: точечный выбор режима, нулевое время,
  отдельные времена/Пуск/Стоп, переключение помп, очередь, сбросы и дата с секундами.
- Короткое/долгое нажатие и удержание с поворотом через реальную GyverEncoder.
- Настоящий цикл приложения, вход в часы, Save/Cancel, обязательное подтверждение RTC.
- Единый журнал программы, атомарное сохранение, прямой сброс выбранной помпы.
- Статические ограничения переводов и отрицательные примеры ошибочных каталогов.

LCD в нативных тестах записывает логические ячейки; это не эмуляция прошивки
HD44780, электрической шины I2C или машинного кода AVR. Ограничения CGRAM
проверяются отдельно по шрифту исходной библиотеки. Энкодерные электрические
импульсы, реальные задержки I2C, запас стека AVR и физическое оборудование
нужно проверять в Wokwi/на плате при соответствующих изменениях.

## CI

.github/workflows/ci.yml выполняет ту же полную команду на ubuntu-latest,
windows-latest и macos-latest. Каждый job строит все четыре варианта прошивки.
Фактически выполненные проверки и их границы перечислены в
[verification.md](verification.md). Наличие ОС в матрице не означает,
что её job уже запускался и прошёл.

Новый сценарий добавляйте в tests/ на Python. Для новой аппаратной функции
сначала расширьте порт и его тестовую реализацию; бизнес-правила остаются C++.

Архитектурные соглашения описаны в [architecture.md](architecture.md) и
проверяются при ревью кода. Тесты проверяют поведение программы; поиск
запрещённых include или расширений файлов в тестовый набор не входит.

LCD-стенд вызывает lcdApplicationBegin/Tick и настоящий core/application.
Команды тестового адаптера передают ввод/время/состояние портов и читают ячейки.
Команда draw_clock используется только для проверки календарной отрисовки;
переходы часов проверяются через реальные пункты меню. Интеграционный стенд
использует тот же applicationTick без интерфейсного ввода. Группового тестового
контракта запуска нет: ручные сценарии используют Mode/Start отдельной помпы.
